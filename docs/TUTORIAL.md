# Учебник: перенести сайт из Figma

Для человека, который впервые видит этот проект. От пустой папки до собранного блока —
одними и теми же командами для любого сайта.

Один прогон уже сделан: `syntonia`. Он и служит примером. Всё, что относится именно к
нему — `fileKey`, страницы, кадры, пути, — лежит в `design/figma/project.json`.
Кода под конкретный сайт нет.

---

## Что нужно

| | |
|---|---|
| Figma | открытый файл в приложении Figma Desktop (не в браузере) |
| мост | `figma-agent` — CLI, который говорит с плагином через локальный WebSocket |
| Node | 22+ |

Проверить мост:

```bash
figma-agent status --peek
```

Живое соединение — можно работать. Нет — откройте файл в приложении и запустите плагин
Design:OS Bridge.

`design/figma/project.json`:


Для нового сайта меняется `fileKey` и имя. Остальное создаётся командами.

## Шаг 1. Снять файл целиком

```bash
npm run intake      # страницы, фреймы, дизайн-система, реальность файла
npm run document    # все 6772 узла со свойствами: переменные, стили, заливки
```

Результат — `design/figma/live/*.json`. В них числа: сколько узлов, стилей, переменных,
привязок. С этого момента у любого утверждения есть версия файла.

**Проверка:** `npm run verify` — сверяет отпечатки выгрузки с живым файлом. Если файл
менялся после выгрузки, скажет.

## Шаг 2. Увидеть объём работы

```bash
npm run structure
```

Создаёт `design/figma/structure.json` — все страницы и все секции со статусами.

Страница `/structure.html` (внутренняя, `noindex`) показывает то же глазами: карточки
блоков, превью «Figma / сделано», числа замеров.

**Правило:** сначала выгружаются **все** секции файла. Пока не видно объёма, любая
оценка сроков — выдумка.

## Шаг 3. Выгрузить одну секцию

```bash
npm run export -- 79:173 --name entry
```

Что появляется в `design/figma/pages/<page>/entry/`:

| файл | что внутри |
|---|---|
| `spec.json` | узлы с координатами, размерами, авто-раскладкой, текстом, заливками |
| `crop.png` | эталон — рендер узла из Figma |
| `gate.json` | результат замеров (появится после `measure`) |
| `pixel.json` | результат пиксельной сверки |

Ассеты — в общий склад `design/figma/assets/{img,svg}`, без дублей.

**Откуда взять `79:173`:** из `/structure.html` или из ссылки на слой в Figma.

Вместе со спекой появляется `states.json` — **все состояния секции в файле**.
Секция живёт не в одном виде: у `formats` пять инстансов, по одному на активный
формат, и у каждого своя картинка слайдера и свои описания вкладок. Выгрузка
одного инстанса даёт одно состояние, остальные теряются молча — именно так
пропали четыре картинки из пяти.

```bash
npm run variants -- 102:220            # посмотреть различия
npm run variants -- 102:220 --name formats --write   # записать states.json
```

Правило: **собрал секцию — покрой все её состояния.** Если в `states.json`
`total` больше единицы, значит в блоке есть переключатель, и каждое состояние
надо нарисовать, а не только первое.

## Шаг 4. Собрать компонент

Можно начать с черновика: `npm run gen -- emit <page>/<section>` кладёт скелет
в `src/components/_gen/`. Он даёт точные координаты и список пропусков, но не
готовую вёрстку: текст и состояния доводятся руками (решение 388). Так же
читаем спеку и переносим — ничего не додумывая:

```bash
node -e "const d=require('./design/figma/pages/home/entry/spec.json'); for (const n of d.nodes) console.log(n.type, n.x, n.y, n.w+'x'+n.h, n.name, n.autoLayout ? n.autoLayout.mode+' gap='+n.autoLayout.gap : '')"
```

Правила, каждое из которых оплачено ошибкой:

| в спеке | в вёрстке |
|---|---|
| `data-figma-node` | атрибут на каждом элементе — без него нечего сравнивать |
| `autoLayout: VERTICAL/HORIZONTAL` | `display: flex` + `flex-direction` |
| `gap` | `gap` |
| `pad: [top, right, bottom, left]` | `padding` |
| `align: STRETCH` | `align-self: stretch` |
| `absolute: true` | `position: absolute` + координаты из `x`,`y` |
| `sizing.h: FILL` | `flex: 1 1 50%` (не `1 1 0` — при `border-box` база не меньше паддинга) |
| `sizing.v: HUG` | высота по содержимому, `max-width` не ставим |
| `fills: IMAGE`, `scaleMode: CROP` | `background-size: 100/m00 × 100/m11`, `position: m02/(1−m00) × m12/(1−m11)` |
| `fills: IMAGE`, `scaleMode: FILL` | **размер `m00×100% × m11×100%`**, позиция та же |
| `strokes` + `strokeWeight` (INSIDE) | `box-shadow: inset 0 0 0 <w>px` — рамка растит высоту |
| `segments` | несколько `<span>` с разными стилями в одном абзаце |
| `lines` | разрыв строки `<br>` |

Только токены: `var(--color-…)`, `var(--space-…)`. Hex в компоненте — дефект.

## Шаг 5. Проверить геометрию

```bash
npm run measure -- design/figma/pages/home/entry/spec.json
```

Печатает таблицу: узел, эталон, что получилось, расхождение. Ворота красные, если
больше 1 px, если у узла глубины ≤ 2 нет своего элемента или если атрибут ссылается
на узел вне спеки.

```
  79:173   0,0,1440,892   0,0,1440,892   0.00  ok
вердикт: зелёные · расхождений 0
```

Красное — почти всегда одна из четырёх причин: лишний/недостающий паддинг, `min-width:
auto` у flex-элемента, рамка, которая растит высоту, или текст, который браузер набирает
шире эталона.

## Шаг 6. Проверить пиксель

```bash
npm run build
npm run shot -- .entry .screens/home-entry.png 1440
npm run compare -- design/figma/pages/home/entry/crop.png .screens/home-entry.png
```

```
средняя разница: 5.10
пикселей > 48:   9.23 %
```

Это сигнал регрессии, а не приёмка: текст растеризуется по-разному, а фон и заливки
совпадают. Ориентиры: 1–2 — почти неотличимо, 5 — заметная разница в фото, 10+ — что-то
не то.

## Шаг 6.5. Проверить, что блок живой и не выдуман

Геометрия и пиксель сходятся и у мёртвой картинки. Эти четыре проверки смотрят
на поведение:

```bash
npm run interactive   # нажатия меняют видимое состояние
npm run motion        # у каждого интерактивного элемента есть переход
npm run layout        # на ширине макета нет горизонтальной прокрутки
npm run invented      # нет вёрстки под ширины, которых нет в кадрах
```

Что каждая ловит и почему появилась:

| проверка | дефект, из-за которого появилась |
|---|---|
| `interactive` | меню, вкладки, слайдер и аккордеон проходили ворота статичными |
| `motion` | блоки сдавались без перехода — «просто картинки» |
| `layout` | шапка 1424 не влезала в кадр |
| `invented` | в `Faq` лежало сжатие на 1100 px, которого в макете нет |

Плюс семь проверок без сборки — одной командой:

```bash
npm run verify   # источники, ассеты, токены, придуманная вёрстка, переносимость,
                 # шаблон холодного старта, значения переменных
```

## Шаг 7. Опубликовать

```bash
npm run previews    # снять собранные секции
npm run structure   # пересобрать /structure.html
npm run page -- --page home --url /   # сверить страницу целиком
```

Порядок важен: `page` читает `structure.json`, а тот обновляется в `structure`. Если
сверять до него, сравнение пойдёт по старому префиксу.

`page` сравнивает только непрерывное начало собранных секций: если между блоками есть
пропуск, дальше сравнивать нельзя — сравнится с чужим блоком.

## Полный цикл одной командой

```bash
npm run export -- <nodeId> --name <slug>   # 1. выгрузка
# 2. собрать компонент и вставить в страницу
npm run measure -- design/figma/pages/<page>/<slug>/spec.json   # 3. геометрия
npm run build && npm run shot -- .<класс> .screens/x.png 1440    # 4. снимок
npm run compare -- design/figma/pages/<page>/<slug>/crop.png .screens/x.png
npm run previews && npm run structure && npm run page -- --page <page> --url /<route>
```

## Частые ошибки и что они значат

| симптом | причина |
|---|---|
| «нет эталона» в структуре | `previews` не прогнан или класс в `shot` не совпал |
| `measure` красный на 8 px по всем узлам | лишний зазор или паддинг у контейнера |
| блок шире эталона на 20–30 px | `min-width: auto` у flex-элемента или рамка |
| текст ломается на две строки | браузер набирает на 1–3 px шире — ширина из спеки |
| картинка с полосами сверху и снизу | `scaleMode: FILL` посчитан формулой CROP |
| битая иконка | файла нет в `public` — `npm run assets:check` покажет |
| `page` сравнивает мало | между собранными секциями пропуск |
