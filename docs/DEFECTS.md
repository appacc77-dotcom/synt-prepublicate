# Дефекты и ворота

Каждый дефект, который уже случался, отвечает на вопрос **«как не повторить»**.
Если ответ «проверка» — она есть в конвейере и падает сама. Если ответа нет,
это честно записано, а не замазано.

Правило: новый дефект сначала превращается в строку этой таблицы, потом в
проверку. Дефект без ворот — долг, а не «норма».

## Чего ворота не ловят

| Дефект | Почему нет проверки | Что делать |
|---|---|---|
| Плашка вокруг длительности «30 мин» | радиус без заливки ничего не рисует — вёрстка дорисовала подложку. Формально это «не додумываем», но автоматически не отличить от настоящей плашки | смотреть кроп перед сборкой; правило в `AGENTS.md` §2.7 |
| Кнопка капсом, когда в файле `caps: false` | текстовое свойство, а замер сравнивает геометрию | сверять `props` инстанса при сборке; обсудить проверку текста по узлу |
| Обводка в quiz отсутствовала | штрих не был пропом компонента | правило: свойство узла → проп (решение 150) |
| `noindex` заявлен в комментарии, но мета-тега нет | проверяется глазами; сейчас тег есть на обеих внутренних страницах | можно добавить проверку `robots` в `check-layout` |

## Как это устроено

- Дефект найден → строка в этой таблице.
- Есть проверка → она в `npm run verify` или в `conveyor`, с кодом возврата.
- Нет проверки → строка в «чего не ловят» с причиной, а не с обещанием.
- Проверка появилась → строка переезжает из второй таблицы в первую.
| Зависшая задача моста выглядит как мёртвый плагин | выгрузка SVG не вернулась, задача стала `outcome-unknown` и заблокировала очередь | коннектор снимает такие задачи сам |
| Сбой одной иконки убивал выгрузку секции | `die()` внутри `runTemplate` | `runTemplateSafe` + `iconErrors` в спеке |
| Размер фона взят из масштаба трансформа | путал `scale` и `1/scale` в CROP | сверка пикселя: 36,22 против 1,73 |
| Ворота привязок рвали транспорт на большой пачке | 30 узлов в одном вызове плагина | пачка 10 + деление пополам при сбое |
| id шагов совпадали у разных страниц | `measure:<секция>` без страницы | полный путь в id + `assertUniqueIds` |
| Ритм и отступы внутри изобретённого компонента | мобильная панель меню: у подменю `padding: 4px 0 4px 16px` — подпункты на 32 px против 16 px, шаг 54 против 50. Компонента нет в макете, значит нет ни узла в спеке, ни кропа, ни записи в карте: замер и пиксель его не видят | **пока нет ворот**: предлагаются ворота ритма (одинаковый шаг и левый край у списка одинаковых элементов) |
| `ds:tokens` падал на пустом проекте | обход `design/figma/pages` без проверки: папки ещё нет до первого экспорта | обход только при наличии папки |
| Каркас ссылался на шрифты, которых сам не кладёт | `BaseLayout` шаблона предзагружал `literata-300-cyrillic.woff2` — шрифт конкретного проекта | предзагрузка убрана, добавлена заглушка `public/fonts/fonts.css` |
| `verify` падал на пустом проекте | `check-bindings` отдавал код 2 при отсутствии секций — «нечего проверять» считалось ошибкой | пустой проект — код 0; отсутствие папки при непустой карте — код 2 |
| `conveyor check --all` падал на пустом проекте | скан `design/figma/pages` без проверки существования, затем семь красных ворот на несуществующих страницах | объём пуст → INCOMPLETE (3) с подсказкой, какие шаги выполнить |
| Замер врал о причине на несуществующей странице | в новом проекте есть только `structure.html`, а `measure` открывал 404 и сообщал «корень секции не размечен» | проверка `dist/<адрес>` до запуска браузера: «страницы нет в dist — сначала соберите её», код 2 |
| Новый проект не проверялся никогда | объём брался из `project.json.acceptance` (пишется руками) либо из скана по `gate.json` (появляется после замера) | скан принимает и `spec.json`: всё экспортированное — объём проверки |
| Шрифтов не было ни в одной команде | файлы `public/fonts/*.woff2` в проекте появились руками, в RUNBOOK шага нет — новый сайт собирался на системных шрифтах | `npm run fonts` (из текстовых стилей файла), `npm run fonts:check` |
| `motion:manifest` падал на новом проекте | запись манифеста без создания `design/motion` | папка создаётся перед записью |
| «Нет dist» при существующем dist | шесть ворот проверяли `dist/index.html` и при его отсутствии сообщали «нет dist/» — хотя сборка есть, в ней просто нет страниц сайта | различаем: нет `dist` → «сначала сборка»; есть `dist` без страниц → «соберите страницы» |
| Восемь красных ворот на несобранном сайте | в новом проекте страницы сайта ещё не собраны, и ворота, которым нужна страница, падали по одной | конвейер отвечает один раз: «страниц сайта в dist нет», код 3 |
| Скрытый слой макета попал в вёрстку | у кнопки «Начать с точки входа» в макете есть слой `arrow-quiet` с `visible: false` — я вывел стрелку, которой в дизайне нет | **правило:** узел с `visible: false` в спеке не верстается. Проверять при сборке: `grep '"visible": false'` по спеке секции |

## Офлайн-сборка из архива .fig (11.11.2026)

Проверка конвейера без моста: страница собиралась из `file-2.fig` одним
kiwi-декодером. Нашлось три класса ошибок — два в нашем экспорте, один в макете.

| дефект | причина | ворота |
|---|---|---|
| заголовок «ПРО ЦЕНТР» наезжал на оранжевую «Я», текст переносился иначе | экспорт не отдавал `fontName` — вёрстка рисовала подставным шрифтом | §9.06: экспорт обязан нести типографику; в спеке появились `font.*` |
| после «исправления» координат всё содержимое уехало на +732/+2518 | `transform` в архиве относителен родителю, а не абсолютен | `spec-bounds` — узлы у рамки обязаны лежать внутри секции |
| три блока выходят за рамку 1464: «Дух / Душа» +29, «Самонаблюдение…» +50, фото +20 | так нарисовано в макете; рамка обрезает их, и в Figma этого не видно | `spec-bounds` показывает их сразу при экспорте |

Чего ворота не делают: не требуют, чтобы текст влезал в свою коробку. В Figma
коробка на 10–15 px ниже строки — это норма, текст не режется. Проверяется
обрезка (`overflow`) и выход за рамку (`spec-bounds`), а не размер коробки.

## Повторная выгрузка теряет иконки (11.11.2026)

Нашлось на волне A, когда перевыгружались секции со смешанными стилями.

| секция | было | стало |
|---|---|---|
| practice/quiz | 1 иконка | 0 |
| practice/practice-package | 5 иконок | 2 |

Инстансы в файле на месте: `I410:1371;14:128` (arrow-quiet, color=white) виден
мостом. Значит, выгрузка не нашла их сама — молча, без ошибки: спека записана,
ворота зелёные, иконка пропала.

**Причина:** `fetch-svg` получал 20 с. Под нагрузкой мост отвечает дольше,
шаблон возвращал пусто, ошибка складывалась в массив и никуда не шла.

**Исправлено (BL-7):**

- таймаут иконки настраивается: `FIGMA_ICON_TIMEOUT_MS`, по умолчанию 45 с;
- сбой иконки останавливает выгрузку **до** записи спеки — старая остаётся целой;
- уменьшение числа иконок против прошлой выгрузки — отказ, обходится
  `--allow-icon-loss` осознанно.

Проверено: practice/quiz 0 → 1, practice-package 2 → 5.

**И рядом, та же болезнь:** выгрузка затирала ручной блок `exclude` в
`states.json` — «это не состояния секции, а другие секции с тем же
компонентом». Теперь он живёт в `states-exclude.json` и переносится в
`states.json` при каждой выгрузке.

## Журнал находок

Этот файл описывает **классы** дефектов и ворота, которые их ловят. Конкретные
находки с причиной, решением и защитой на будущее — в [`ISSUES.md`](ISSUES.md)
(источник `issues.json`, собирается `npm run issues:write`). Очередь
рефакторинга берётся оттуда.
