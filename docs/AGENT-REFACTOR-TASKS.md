# Доработки конвейера этапа 1 — задачи агенту

Ветка: `refactor/studio-stage1`. Документ — продолжение концепции студии
(«Агентная веб-студия: концепция v0.2 и рефакторинг этапа 1»): этап 1 —
перенос макета Figma в код — доделывается, этап 2 в разработке, остальные
не начаты. Здесь — что уже сделано в ветке, как это проверить на Mac и какие
карточки остались.

## Правила работы

- **Маленькие коммиты.** Одна карточка — один коммит, сообщение по-русски,
  `fix(…)` / `feat(…)` / `docs(…)`.
- **Не ломать.** После каждой правки — `node tools/conveyor.mjs check --all`.
  Статусы шагов и числа `gate.json` должны совпасть с прогоном до правки,
  кроме тех, что правка меняет намеренно. Красное неожиданно — откат
  (`git revert`), а не починка поверх.
- **Без общих библиотек.** Не выносить код в `harness`, `conveyor-core`,
  `measure-core` и подобное. Каждый инструмент остаётся самостоятельным
  файлом в `tools/`.
- **Без больших переписываний.** Владелец уже откатывал большой рефакторинг.
  Правка, которая трогает больше 3 файлов или 150 строк, — сначала вопрос
  владельцу.
- **Ничего не изобретать.** Всё, чего нет в макете, — запись в
  `design/figma/invented.json` и пометка `data-invented="<id>"` в разметке.
  Без записи ворота `registry` красные.
- **Пуш.** Хук `post-commit` пушит только после полного зелёного прогона на
  том же содержимом (`node tools/conveyor.mjs push-ok`). Иначе коммит
  локальный, отправить вручную: `git push`. Осознанный обход:
  `CONVEYOR_PUSH=force git commit …`.

## Проверка ветки на Mac

1. `git status` — чисто. `git fetch origin && git checkout refactor/studio-stage1`.
2. `node -v` — не ниже 22.23.4 (Astro 7.4.5). `npm ci`.
3. Если хуки ещё не включены: `git config core.hooksPath tools/git-hooks`.
4. Figma desktop: открыт «Website Syntonia2», плагин моста запущен.
5. `node tools/conveyor.mjs check --all` — полный прогон.
6. Сравнить с прогоном на `main` (тот же шаг на `main` до переключения):

   | Шаг | Ожидание |
   |---|---|
   | все `measure:*` | как на `main`; `gate.json` без изменений, кроме `at` (а `at` теперь не пишется, если числа те же) |
   | `images` | зелёный |
   | `registry` | новый шаг, зелёный (1 предупреждение: `booking-form-not-sent` без номера решения) |
   | `sources` | как на `main`; если стал INCOMPLETE — смотреть список «не прочитано»: это секции без отпечатка, раньше они молча пропускались |
   | `bindings` | **главное место проверки.** Печатает «проверено N из M» и «пропущено …». Если появился код 3 с `no-binding` — в спеках привязки, которых нет в файле: перевыгрузить эти секции. Если `alias-chain` много — это ссылки переменная→переменная, их сверка — отдельная карточка (R2.6) |
   | остальные | как на `main` |

7. Пиксель `home/faq` (`--unit home/faq`): средняя разница должна остаться
   ≈ 4,31 (фон при 807 px отличается на ~1,7 px по вертикали).
8. Всё как ожидалось → слить PR. Неожиданно красное → не сливать, вывод
   прогона — владельцу.

## Что в песочнице проверить нельзя

- **мост** (`sources`, `bindings`, экспорт) — в песочнице нет Figma;
- **замеры**: шрифты Linux дают другую ширину текста — 30 секций там красные
  на 2–73 px, на Mac все зелёные. Числа замера доверять только Mac;
- **хук пуша** — в клоне песочницы хуки не установлены.

## Карточки

Формат: что, зачем, критерий приёмки (DoD). Порядок — сверху вниз.

### Волна 2 — остатки

**R2.4. Пограничные секции по допуску.** У home/entry, home/formats,
home/quiz, method/method-cta, quiz/quiz-result худшее отклонение ровно 1,00 px
при допуске 1. Найти узел с этим отклонением, понять причину (округление,
трекинг, `line-height`).
DoD: у каждой из пяти либо `worstDelta` < 0,9, либо запись в
`docs/decisions.md`, почему 1 px — свойство данных.

**R2.5. Интерактивность: скрытая секция — «не проверено», а не пропуск.**
`check-interactive` пропускает скрытые секции (экран результата квиза
`qres`) и не отражает это в итоге.
DoD: скрытая секция с элементами управления → код 3 (INCOMPLETE) с именем
секции, либо явный список «проверяется после действия» с шагом открытия.

**R2.6. Привязки: ссылки переменная → переменная.** Шаблон
`check-bindings.template.js` пропускает значения `VARIABLE_ALIAS`
(`alias-chain`). Разрешать цепочку до цвета (не глубже 5 шагов).
DoD: `alias-chain` в отчёте 0 или каждая — с причиной.

**R2.7. Состояния: красный `gate.json` — не «собрано».** `check-states`
берёт секцию, если `gate.json` существует, не глядя на `ok`.
DoD: секция с `ok: false` даёт INCOMPLETE с именем, а не проверяется как собранная.

**R2.8. Форма заявки: решение владельца.** Долг `INV-booking-form`: сообщение
«Форма не отправляется» на «Форматах» без записи в журнале.
DoD: номер решения в `invented.json` → `booking-form-not-sent.decisions`,
предупреждение `registry` исчезло.

**R2.9. Сборка «только из макета» (флаг `figma-only`).** Сборка без
изобретённого: элементы с `data-invented` не попадают в `dist` — чтобы
показать дизайнеру, что на сайте строго из макета.
DoD: `npm run build -- --figma-only` (или переменная окружения) даёт `dist`
без элементов с `data-invented`; замеры всех секций те же.

**R2.10. Закрытие этапа 1.** Отчёт по `docs/debts.json`: что открыто, у кого,
что блокирует сдачу (сейчас D-1, D-3).
DoD: `node tools/status.mjs` печатает блок «закрытие этапа 1»; долги с
`blocksRelease` закрыты или переведены владельцем в `rejected` с причиной.

### Волна 3 — изменения макета

**R3.1. Снимок файла `snapshot.json`.** Версия файла, отпечатки всех секций,
время — одним файлом после `intake`.
DoD: файл в репозитории, обновляется командой, `verify-sources` читает его.

**R3.2. Разница снимков.** `node tools/snapshot-diff.mjs A B` — какие секции
изменились, появились, исчезли.
DoD: на подмене одного отпечатка показывает ровно эту секцию.

**R3.3. Запросы на изменение `changes/CR-NNN.md`.** Изменение макета после
сдачи — не правка «по месту», а запрос: что изменилось (из разницы снимков),
какие секции, цена, решение владельца.
DoD: шаблон и один пример; конвейер не начинает пересборку секции без CR.

**R3.4. (Необязательно) вебхук `FILE_VERSION_UPDATE`.** Только на тарифе
Figma Professional и выше. Уведомление о новой версии файла →
`snapshot-diff`.
DoD: решение владельца о тарифе в журнале; без него — не делать.

### Волна 4 — проверка без автора

**R4.1. Визуальный проверяющий только на чтение.** Отдельный агент
сравнивает снимок секции с кропом и пишет `reviews/<run>/<unit>.json`:
список замечаний с координатами. Ничего не правит.
DoD: на 3 секциях с известными дефектами находит их; на зелёной — ноль замечаний.

**R4.2. Набор регрессии ~20 секций.** Фиксированный список с разным типом
(текст, фото, состояния, общие шапка/подвал) для быстрого прогона.
DoD: `check --set regression` за время ≤ трети полного.

**R4.3. Точки возобновления прогона.** Упавший полный прогон продолжается с
шага, а не с начала.
DoD: `check --all --resume <runId>` пропускает PASS-шаги того же `contentHash`.
