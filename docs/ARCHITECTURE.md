# Архитектура, процесс и решения — Syntonia

Файл для чтения человеком. Агентская версия — `AGENTS.md` и `docs/system/`.
Здесь: как устроено, что уже проверено числами и какие решения приняты.

Обновляется по ходу работы. Последнее обновление — 06.11.2026.

## 1. Что строим

Не сайт, а **конвейер**: живой макет Figma → числа → компоненты → страницы →
проверки. Сайт — побочный продукт; ценность в том, что результат воспроизводим
командой, а не «выглядит похоже».

Предыдущая попытка дала 13 страниц за двое суток и приёмку с **escape rate 33%**:
пять дефектов из пятнадцати карточек нашлись уже после «готово». Причина не в
скорости — в том, что ворот не было ни одних.

## 2. Режим: только живой мост

Единственный источник истины — файл, открытый в Figma desktop, через
`figma-agent` (DESIGN:OS Bridge).

| | |
|---|---|
| Файл | «Website Syntonia2» |
| `fileKey` | `NInjODHyOOjIitF3lq4Vpe` |
| Канонические фреймы | Home `79:103`, Method `323:422`, Masters `217:237`, Library `267:450`, Practice `408:241`, Quiz `529:118`, Booking `383:286` |

Ни `.fig`, ни заранее выгруженных PNG в проекте нет. Причина простая: прежние
эталоны были выгружены из **другого** файла (`wbtBZLldiNMyOD4vX8ukKz`), и
сравнение с ними давало числа, которых не существует в природе.

## 4. Цикл работы (образец — hero)

1. **Узел.** `exec-js` обход дерева: `read-tree.js` → координаты, размеры,
   авто-раскладка, видимость, тексты, заливки.
2. **Спека.** Числа из дерева → `design/figma/pages/<page>/<section>/spec.json`.
3. **Кроп.** `figma-agent export-png --node <id>` → `design/figma/pages/`.
4. **Ассеты.** Фото — по `imageHash` (`getImageByHash().getBytesAsync()`), иконки —
   `exportAsync({format:'SVG'})`. Не рисуются руками.
5. **Сборка.** Компонент из токенов; размеры не вписываются под место вызова.
6. **Замер.** `npm run measure` — геометрия против спеки, exit 1 при Δ > 1 px.
7. **Пиксель.** `npm run compare` — сигнал регрессии, не критерий приёмки.

Правило, которое дало результат на hero: **ширина кнопки не задаётся**. 303 px
получаются из `16 + 249 + 8 + 14 + 16`. Раньше в `Button.astro` стояло
`width: 303px` и ещё семь таких же — и это считалось нормой.

## 5. Модули и инструменты

Конвейер разбит на **четыре крупных модуля**, а не на восемь мелких: мелкие
модули дают свару в каталоге скилов, и агент выбирает не тот.

| Модуль | Фаза | Что делает | Состояние |
|---|---|---|---|
| `figma-intake` | P0–P1 | снимок живого файла: структура, дизайн-система, реальность, дрейф | **готов** |
| `figma-model` | P2–P3 | спека секции, кроп, ассеты, токены | **готов**: `export` + `ds:tokens` |
| `figma-build` | P4 | сборка компонента по спеке | **готов**: процедура в скиле |
| `figma-structure` | P7 | карта переноса и визуальные сравнения | **готов**: `/structure.html` |
| `figma-document` | P1 | полный дамп файла | **готов**: `live/document.json` |
| `gates` | G1–G2 | девять проверок: геометрия, пиксель, источники, ассеты, токены, придуманная вёрстка, переносимость, шаблон, значения переменных | **готовы**: связь через `data-figma-node` |

Модуль 1 — `npm run intake`:

- проверяет, что мост жив и открыт **тот** файл (`fileName` и `fileKey`);
- снимает `live/{structure,ds,reality}.json`;
- пишет `snapshot.json` с временем, `fileKey` и числом инстансов по страницам;
- **ловит дрейф**: если с прошлого снимка файл правили, печатает, где именно
  изменилось, и предупреждает, что спеки и кропы могли устареть.

Коды возврата: `0` — снято, `1` — открыт другой файл, `2` — мост недоступен,
`3` — скрипт Figma вернул ошибку.

### Ворота

`npm run verify` — не отдельная цепочка, а псевдоним профиля: `check --profile
accept-stage1 --cache`. Раньше это был свой список из семи инструментов, и он
расходился с конвейером (например, требовал живой мост там, где приёмка
обходится снимком). Прежний текст о пяти проверках, которым не нужен
`dist/`. Остальные требуют собранной страницы.

| Проверка | Что ловит | `dist/` |
|---|---|---|
| `measure` | элемент с `data-figma-node` разошёлся с узлом больше 1 px | да |
| `compare` | картинка разошлась с кропом (сигнал регрессии, не приёмка) | да |
| `interactive` | блок мёртвый, притворяется или перекрыт | да |
| `motion` | переключение рывком, нет перехода | да |
| `layout` | горизонтальная прокрутка на ширине макета | да |
| `verify` → `verify-sources` | экспорт устарел: отпечаток не совпал с файлом | нет |
| `verify` → `assets:check` | ассет в разметке, но не в `public` | нет |
| `verify` → `tokens:check` | `var(--x)` без определения — свойство молча исчезает | нет |
| `verify` → `invented` | вёрстка под ширину, которой нет в кадрах | нет |
| `verify` → `portability` | инструмент или скил знает про конкретный проект | нет |
| `verify` → `scaffold:check` | шаблон холодного старта отстал от конвейера | нет |
| `verify` → `bindings` | в спеке хранимое значение вместо значения переменной | нет |

Правило: каждый класс ошибки, который уже случался, становится проверкой с
кодом возврата. Список вырос с двух до девяти именно так — каждая новая
проверка появилась после реального дефекта, а не заранее.

### Скилы

Каждый модуль — тонкий `SKILL.md` в `~/.agents/skills/` поверх скриптов проекта.
Скил держит порядок и стоп-условия, скрипт — механику и exit code. Всё
проектное вынесено в `design/figma/project.json`, поэтому на другом сайте
меняется один файл, а не инструкции.

| Скил | Когда берётся |
|---|---|
| `figma-intake` | в начале работы и после правок макета |
| `figma-export` | перед сборкой: кроп, ассеты, спека |
| `figma-build` | сборка по спеке |
| `figma-gates` | проверка и приёмка |
| `figma-structure` | карта и публикация сравнений |

### Команды

| Команда | Что делает | Ворота |
|---|---|---|
| `npm run intake` | снимок живого файла | **да**, exit 1 при чужом файле |
| `npm run export -- <node> --name <slug>` | кроп, ассеты, `spec.json` секции | **да**, exit 1 при чужом файле |
| `npm run ds:tokens` | токены и типографика из живого файла | — |
| `npm run shot -- <sel> <out> <w>` | снимок элемента через Playwright | — |
| `npm run measure -- <spec.json>` | DOM против спеки по `data-figma-node` | **да**, exit 1 при Δ > 1 px |
| `npm run compare -- <crop> <shot>` | пиксельная сверка | сигнал |

`compare` написан на Node с разбором PNG через `zlib` — внешних зависимостей нет
(первая версия требовала Pillow и не запускалась на системном Python).

## Два слоя результата

Результат делится на два слоя, и это правило, а не идея.

| | слой 1 `base` | слой 2 `enhancements` |
|---|---|---|
| основание | версия Figma и согласованные уточнения | решения студии и владельца |
| что входит | компоненты, тексты, состояния, визуальные свойства из файла | адаптив, движение, поведение, интеграции |
| нельзя | додумывать отсутствующее | незаметно менять принятую основу |
| приёмка | `--profile accept-stage1` | `--profile accept-stage2` |

Анимация или состояние не становятся слоем 2 автоматически: задано файлом —
обязательство слоя 1, придумано студией — слоя 2.

**Граница проверяется, а не декларируется:**

- `npm run build:base` — сборка без дополнений: не только разметка, но и
  обработчики, и движение (`<html data-enhancements="off">`);
- ворота `enhancement-off` — в base-сборке нет ни изобретённых элементов, ни
  обработчиков, ни переходов;
- ворота `base-parity` — собирает обе версии и сравнивает `gate.json` всех
  секций: дополнение не имеет права двигать основу без записи в
  `allowedSections`.

## Проверки с контрактом

`tools/checks.json` описывает каждую проверку: слой, охват, входы,
зависимости, ресурсы, свой таймаут, политику повторов, выходы и в каких
профилях она обязательна. Инструменты остаются самостоятельными — файл читает
конвейер, а не они.

**Профили** вместо флагов: `local` (единица и зависимости, без моста),
`regression` (контрольный набор), `accept-stage1`, `accept-stage2`,
`sources-live` (сверка с живой Figma). Старые `--all`, `--set`, `--unit`
остаются псевдонимами.

**Граф.** Порядок шагов выводится из `dependsOn`; шаг с непрошедшей
зависимостью получает `BLOCKED` с её именем, а не ERROR и не тишину.

**Кэш** (`--cache`) переиспользует результат, если совпали входы, инструмент и
окружение. Красный результат не кэшируется никогда.

## Генератор: черновик разметки

`tools/gen.mjs` собирает скелет секции из спеки абсолютной раскладкой. Это
**не поставщик вёрстки** (решение 388): пиксель проигрывает ручной сборке там,
где текст лежит поверх изображений и где есть состояния. Ценность черновика —
точная геометрия (measure зелёный во всех классах) и полный список того, что
требует рук.

```
node tools/gen.mjs plan   home/method   # что попадёт в вёрстку, что в overrides
node tools/gen.mjs emit   --all         # src/components/_gen/*.astro
node tools/gen.mjs report               # покрытие, расхождения, overrides
```

Правила: генератор пишет только в `src/components/_gen/`; всё, что нельзя
нарисовать из чисел (вектор, инстанс без детей, скрытый слой), уходит в
`design/gen/overrides/<section>.json` с причиной и номером решения. В сборку
сайта черновик не входит: калибровочная витрина `/gen.html` удалена вместе с
шестью секциями (числа остались в `docs/GEN-CALIBRATION.md`).

Перенос черновика в рабочий компонент — обычный путь: `src/components/`,
Definition of Done, замер, пиксель, состояния, `review`. Исключений для
сгенерированного кода нет.

Ворота: `gen-drift` (файл поправлен руками), `gen-coverage` (порог
`project.json.gates.genCoverage`), `gen-overrides` (пропуск без причины).

Чего нет: auto-layout. В спеке только координаты и `sizing` — полей раскладки
нет, поэтому вёрстка абсолютная. Кроп картинок воспроизводится по
`imageTransform` точно.

## Чтение .fig без Figma

`tools/fig-kiwi.mjs` разбирает архив целиком: схему и данные, до дерева узлов.

```
node tools/fig-kiwi.mjs inspect    <file.fig>          # паспорт и список страниц
node tools/fig-kiwi.mjs pages      <file.fig>          # страницы и их фреймы
node tools/fig-kiwi.mjs tree       <file.fig> "Booking" 2
node tools/fig-kiwi.mjs crosscheck <file.fig>          # архив ↔ спеки
```

Экспорт из архива несёт то же, что мост, кроме состояний и кропа:

| поле | откуда берётся |
|---|---|
| `styleName` | узел с `styleType` и именем («H2», «quote») — это и есть стиль, ссылка `styleIdForText`/`styleIdForFill` ведёт на его guid |
| `bound` | `variableConsumptionMap`: поле и ссылка `VariableID:<s>:<l>` |
| `font` | `fontName`, `fontSize`, `lineHeight`, `textTracking`, `textAlignHorizontal` |

Имена полей в `bound` приведены к одному виду (`STACK_SPACING` → `stackSpacing`).
У моста свои имена (`itemSpacing`) — смешивать две записи в одной спеке нельзя,
поэтому офлайн-спеки и спеки моста не должны складываться в один каталог.

`crosscheck` — сверка с выгрузкой: размеры секций в архиве и в спеках должны
совпадать. Число узлов не сравнивается: в архиве инстансы не раскрываются
(634 инстанса, ни у одного нет детей), а спека их раскрывает — счётчик в
архиве был бы нижней границей и врал бы «узлы потерялись».

Декодер знает формат **kiwi v106**; на другой версии он отказывается читать
(код 3), а не разбирает молча: рассинхрон формата выглядит как правдоподобные,
но неверные числа.

Зачем свой разбор: мост показывает файл сейчас, архив — что было в момент
выгрузки. Это второй независимый источник, без Figma и без плагина.

Ключевые места формата, на которых легко разъехаться:

| | |
|---|---|
| `MESSAGE` | пары «номер поля + значение» до нуля; номера не совпадают с порядком полей |
| `STRUCT` | поля подряд, без номеров |
| строка | до нулевого байта |
| дробь | ноль — один байт, иначе четыре с поворотом бит на 9 |
| `uint64` | LEB128, но после 56 бит продолжение не учитывается |

Последнее неочевидно: обычный LEB128 читает на два байта дальше, и разбор
уезжает на поле `strokeSeed` — дальше всё рассыпается.

## Два `structure.json`

Имена совпадают, смысл разный — путались не раз.

| файл | что это | кто пишет |
|---|---|---|
| `design/figma/live/structure.json` | снимок живого файла: страницы и секции, как они есть в Figma | `npm run intake` (через мост) |
| `design/figma/structure.json` | данные страницы `/structure.html`: статусы, числа, превью | `npm run structure` (из артефактов) |

Первый отвечает на вопрос «что в макете», второй — «что сделано». Второй
читает первый как вход.

## Реестры

| файл | что |
|---|---|
| `design/figma/invented.json` | изобретённые элементы внутри секции, ссылаются на дополнение |
| `design/enhancements.json` | дополнения слоя 2: зачем, откуда, кем согласовано, что разрешено менять, как отключается, чем проверяется |
| `docs/debts.json` | долги с владельцем и блокировкой сдачи |
| `changes/CR-NNN.md` | запросы на изменение макета после сдачи |

## Мастерская и выпуск

Репозиторий — мастерская: спеки, кропы, отчёты, студийные страницы, `design/`
на 250 МБ. Клиенту это не нужно и вредно: медленный клон, лишний вес, риск
показать рабочую страницу.

Выпуск — отдельный набор, описанный в `site-files.json`. Его собирает
`tools/site-export.mjs`:

```
site-files.json → копия набора → сборка RELEASE=1 → site-manifest.json
                                        ↓
                             ветка site (генерируемая)
                                        ↓
                          Netlify собирает и раздаёт
```

Контракт — машина, а не договорённость. Манифест пишет коммит мастерской, хеш
набора и `runId` зелёного прогона приёмки. Ворота `site-contract` не пускают
публикацию, если прогон не зелёный, снят с грязного дерева, относится к
другому коммиту или набор изменился после экспорта.

Студийные страницы (`structure.html`, `ds.html`) и превью в выпуск не входят:
они тянут `design/` и живут в мастерской (решение 400).
