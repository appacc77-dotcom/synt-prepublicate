# Калибровка генератора: критерии до замера

Пилот на двух секциях (`home/method`, `home/process`) показал: геометрию и
кроп картинок генератор держит, текст — нет. Чтобы понять **масштаб разрыва**,
пилот расширен на шесть секций по классам. Критерии выписаны заранее, до
первого замера, — иначе под результат подгоняется порог.

## Шесть классов

| класс | секция | чем интересна |
|---|---|---|
| текстовая | `home/faq` | десять текстов с разной типографикой, в файле смешаны стили (FI-5) |
| карточки с вариантами | `home/formats` | четыре карточки одного компонента, пять состояний |
| фото в кадре | `masters/founder-hero` | четыре фотографии, кроп из `imageTransform` |
| карусель | `home/voices` | двенадцать слайдов, двадцать инстансов — заведомо уйдёт в overrides |
| форма с состояниями | `booking/booking-formats` | самая тяжёлая: 144 узла, пять состояний, 57 текстов |
| контроль простой | `method/method-about` | 18 узлов, чистая раскладка «текст и линии» |

## Что считается

По каждой секции четыре числа и одно заключение:

1. **покрытие** — доля узлов, собранных генератором из спеки;
2. **overrides** — сколько узлов ушло руками, с разбивкой по причинам;
3. **дельта пикселя** — `генератор − ручная сборка`, по одному и тому же кропу;
4. **measure** — зелёный или красный, с числом расхождений;
5. **review** — первые замечания визуального проверяющего (не больше трёх).

## Пороги: заранее

### Геометрия

Красный, если `measure` нашёл расхождение больше 1 px, или у узла глубины ≤ 2
нет своего элемента в разметке. Пропуск узла, ушедшего в overrides, — не
расхождение: его геометрия не проверяется по определению.

### Покрытие

| класс | порог покрытия | почему |
|---|---:|---|
| контроль | 95 % | почти всё — рамки и текст |
| текстовая | 95 % | текст генерируется целиком |
| карточки | 90 % | иконки и векторы внутри карточек уйдут в overrides |
| фото | 85 % | маски и векторные акценты поверх фото |
| форма | 80 % | 18 инстансов, часть с состояниями |
| карусель | 30 % | каждый слайд — инстанс; низкое покрытие ожидаемо и не является провалом, если **каждый** пропуск объяснён |

### Overrides

Красный, если хоть одна запись без причины или без номера решения — это
пропуск, о котором никто не знает. Разбивка по причинам обязательна: она
показывает, где генератор упирается **классом**, а не узлом.

### Пиксель

Сравниваем с ручной сборкой той же секции, а не с абсолютом: у классов разный
потолок (фото и карусель в принципе дальше от кропа, чем текст).

| дельта `генератор − ручной` | вердикт |
|---:|---|
| ≤ +0.5 | **зелёный** — не хуже ручного |
| +0.5 … +1.5 | **жёлтый** — хуже, но в пределах шума класса |
| > +1.5 | **красный** — генератор проигрывает заметно |

Дополнительно: абсолют генератора не выше ручного **+1.0** для классов
«текстовая», «контроль» и «карточки» — там ручная сборка эталонна.

### Review

Не больше трёх замечаний на секцию; каждое — область с координатами из
`reviews/<run>/<unit>.json`. Ноль замечаний — тоже результат, его пишем.

## Как считается

```
node tools/gen.mjs plan --all                 # что генерируется, что в overrides
node tools/gen.mjs emit --all                 # src/components/_gen/*.astro
node tools/gen.mjs report --all               # покрытие и расхождения
node tools/measure.mjs design/figma/pages/<unit>/spec.json --url /gen.html
node tools/shot.mjs --node <id> .screens/gen-<section>.png 1440 --url /gen.html
node tools/compare.mjs design/figma/pages/<unit>/crop.png .screens/gen-<section>.png
node tools/review.mjs --unit <unit>           # по снимку .screens/<page>-<section>.png
```

Ручная сборка меряется тем же способом на `/index.html`, `/booking.html` и
других страницах сайта: кроп один и тот же.

### Overrides по причинам

| причина | всего | где |
|---|---:|---|
| вектор: нужен SVG | 63 | faq 12, voices 21, formats 8, booking 8, founder-hero 6 |
| скрытый слой (`visible: false`) | 15 | booking 10, founder-hero 4, formats 1 |

Ни одного пропуска без причины и номера решения — ворота `gen-overrides`.

### Что показал замер

**Геометрия держится полностью.** Шесть из шести — `measure` зелёный,
0 расхождений. Абсолютная раскладка по координатам спеки воспроизводит
положение узлов точно, включая вложенные.

**Пиксель расходится тем сильнее, чем больше в секции текста и состояний.**

- контроль и текст — **+1.2** (жёлтый по нашим порогам): почти всё сходится,
  расхождение в метриках строки;
- карточки — **+1.6** (красный, на границе): карточки совпали, но текст
  внутри них уже уезжает;
- фото, карусель, форма — **+7** (красный): там, где много текста поверх
  изображений и вариантов, разрыв большой.

### Что нашлось и починилось по дороге

Четыре ошибки генератора, каждая видна числом:

| что было | симптом | стало |
|---|---|---|
| не пропускались `visible: false` | тела аккордеона легли друг на друга, `founder-hero` 36.04 | 13.24 → 12.15 после остальных правок |
| `imageTransform` применялся и к `FILL` | кадр фото уезжал, `founder-hero` 31.86 | `FILL` → `cover`, `CROP` → по матрице |
| фон секции-картинки не рисовался | `formats` 12.38, `voices` 19.07 — белое поле | 3.71 и 13.23 |
| токен по цвету вместо имени переменной | «стекло» на 75 % стало непрозрачным белым | `var(--color-bg-glass-strong)` |

### Где порог оказался неверным

**Текстовая секция не прошла порог 95 %** — и это ошибка критерия, а не
генератора: в `home/faq` 12 из 51 узла — иконки-стрелки (векторы), они
по определению уходят в overrides. Потолок для этой секции 76 %.
Критерий писался до замера и остаётся как есть: в следующий раз порог для
текстовых секций ставится после просмотра состава узлов, а не по названию
класса.

По той же причине `home/formats` не дотянула до 90 % (88 %): 8 векторов и
1 скрытый слой.

## Вывод

| вопрос | ответ |
|---|---|
| держит ли генератор геометрию | **да**, шесть из шести зелёные |
| тянет ли пиксель | **нет** для секций с текстом поверх изображений и с вариантами; для простых — в пределах +1.2 |
| что мешает | метрики строки (абсолютная раскладка не повторяет доводку ручных компонентов), состояния (рисуется один вариант), векторные иконки |
| где генератор уже полезен | секции без поведения: контроль, простые текстовые блоки, разметка карточек — там разрыв 1.2–1.6 и он объясним |

**Решение владельца (11.11.2026): оставляем генератор как черновик
разметки.** Он даёт точную геометрию и полный список того, что требует рук,
и не претендует на готовую вёрстку. Доводку текста и состояний в генератор
не добавляем — это работа руками по обычному Definition of Done.

Что это значит на практике:

- сгенерированный файл в `src/components/_gen/` — скелет, из которого берут
  разметку, а не компонент, который идёт в приёмку;
- перенос в `src/components/` — обычный путь: имена, токены, `data-figma-node`,
  замер, пиксель, состояния, `review`;
- `design/gen/overrides/` — это и есть рабочий список: каждый пропуск с
  причиной показывает, что нужно доделать руками;
- ворота генератора остаются: черновик обязан воспроизводиться
  (`gen-drift`), не терять узлы (`gen-coverage`) и объяснять пропуски
  (`gen-overrides`).
