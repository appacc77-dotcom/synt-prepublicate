# figma-export

Один вызов снимает с узла всё, что нужно для сборки блока: эталон, ассеты и
числа. Ничего не выгружает заранее и не хранит рендеров «на память».

## Когда брать

- перед сборкой компонента или секции по макету;
- когда нужен эталон для пиксельной сверки;
- когда у блока есть фото или иконки и их надо забрать из файла, а не рисовать.

## Когда не брать

- файл закрыт или плагин не запущен — сначала `figma-agent status --peek`;
- нужно понять, что вообще есть в файле — это `figma-agent scan-design-system`
  и `exec-js`, а не экспорт;
- нужно менять макет — этот скил только читает.

## Контракт проекта

Скил не знает путей: он читает `design/figma/project.json`.

```json
{
  "source": { "fileName": "...", "fileKey": "..." },
  "paths": { "live": "design/figma/live", "sections": "design/figma/sections", "styles": "src/styles" },
  "gates": { "geometryTolerancePx": 1, "pixelDelta": 16 }
}
```

Результат складывается в `design/figma/pages/<page>/<section>/`:

| Файл | Что это |
|---|---|
| `spec.json` | факты: узлы, координаты, размеры, текст со всеми свойствами, заливки, обводки, эффекты, авто-раскладка, привязки к токенам, варианты компонентов |
| `crop.png` | эталон, снятый с самого узла в масштабе 1 |

Ассеты — **в общем складе**, не в папке секции: `design/figma/assets/img/<hash>.jpg`
и `design/figma/assets/svg/<component>-<variant>.svg`.

**Иконка дедуплицируется по компоненту И варианту.** У `arrow-quiet` восемь
сочетаний `color × direction`; если ключом делать только компонент, все стрелки
получат направление первого инстанса. Имя файла собирается из значений свойств:
`arrow-quiet-white-right.svg`.

После смены схемы имён старые файлы остаются в складе — `npm run assets:prune`
удаляет всё, на что не ссылается ни одна спека. Одно фото и одна иконка на весь
проект; спека ссылается на путь в складе. Иначе `arrow-quiet.svg` лежит в каждой
из тридцати секций, а текстура кнопки — в двадцати (проверено: 167 МБ → 66 МБ).

## Порядок

1. **Снимок файла.** `npm run intake` — проверяет, что открыт тот файл, и
   замечает, если макет менялся с прошлого раза. Числа без этого шага не имеют
   версии.
2. **Экспорт.** `npm run export -- <nodeId> --name <slug>`.
3. **Прочитать `spec.json`.** Смотреть на `autoLayout`, `fills`, `styleName` —
   из них собирается CSS, а не из глаз.
4. **Собрать компонент.** Размеры не вписывать под место вызова: если не
   сходится, виноват шрифт, трекинг или паддинг.
5. **Замер.** `npm run measure -- design/figma/pages/<page>/<section>/spec.json` —
   геометрия по `data-figma-node`, exit 1 при расхождении больше 1 px.
6. **Пиксель.** `npm run shot -- .<class> .screens/<slug>.png 1440` и
   `npm run compare -- design/figma/pages/<page>/<section>/crop.png .screens/<slug>.png`.
   Это сигнал регрессии, а не критерий приёмки: текст растеризуется по-разному.

## Что экспорт решает сам

- **Фото.** Обходит дерево, берёт `IMAGE`-заливки, достаёт байты по
  `imageHash`, дедуплицирует по хешу. Не гадает про кроп — `imageTransform`
  остаётся в спеке, переносить его в CSS нужно осознанно.
- **Настройки изображения.** `filters` (экспозиция, насыщенность, контраст)
  пишутся в спеку рядом с хешем. Без них фон уезжает по цвету целиком: у секции
  `pain` exposure +0,35 и saturation −0,13 превращают бежевое фото в выбеленное,
  и расходится не пятно, а каждый пиксель. Переносятся **запеканием в файл**
  (`bake-image.mjs`), причём кривая снимается с рендера: формула Figma не
  описана. Провенанс пишется в `pages/<page>/<section>/image.json`.
- **Иконки.** Инстанс без текста внутри и не больше 64 px — это иконка. SVG
  берётся у главного компонента и дедуплицируется по набору, поэтому тридцать
  кнопок со стрелкой дают один файл.
- **Числа.** Пишет всё, что отдал узел, не отбрасывая неудобное: масштаб,
  скрытые слои, вложенность.

## Разметка: как вёрстка связана с макетом

Элемент помечается `data-figma-node="<id>"` — id узла из спеки. Замер сам
находит такие элементы и сверяет с узлами; отдельного файла соответствий нет,
забыть строку нельзя.

- несколько id через пробел, если разметка схлопывает служебные фреймы:
  `<section data-figma-node="79:105 79:106">`;
- узел глубины ≤ 2 без элемента — красные ворота: часть секции не собрана;
- атрибут на узел вне спеки — тоже красные: разметку скопировали из другой
  секции или узел переименовали;
- координаты считаются от корня секции, поэтому DOM-дерево вправе отличаться от
  Figma — важно совпадение геометрии, а не совпадение вложенности.

## Сверка с .fig (необязательно, но полезно)

Если под рукой есть `.fig` того же файла — это независимая проверка полноты:

```bash
npm run fig inspect <file.fig>   # meta, версия kiwi, число картинок
npm run fig verify  <file.fig>   # картинки склада байт в байт + тексты спек
```

`.fig` — ZIP: `meta.json`, `canvas.fig`, `images/<sha1>`. Канвас — `fig-kiwi`:
магия, версия, длина схемы, схема (raw deflate), длина данных, данные (zstd).

**`.fig` не источник.** Если он от другого `fileKey` или старше живого файла,
данные из него устаревшие — берём только для сверки, не для сборки.

## Текст: две ловушки

- Figma пишет перевод строки как **U+2028**, а не `\n`. В спеке это `lines` —
  сборка обязана развернуть в `<br>`, иначе строки склеятся.
- Неразрывный пробел приходит как **U+00A0** (`nbsp`): его нельзя схлопывать,
  он держит «3 встречи» вместе.

## Стоп-условия

- `fileKey` не совпал с `project.json` — открыт другой файл, работа
  останавливается (exit 1);
- мост недоступен или плагин не отвечает (exit 2) — не выдумывать размеры;
- в спеке нет нужного узла — сначала `figma-agent inspect <id>`;
- у узла есть фото, а в `assets/img/` его нет — экспорт неполный, перезапустить.

## Ловушки, за которые уже заплачено

| Симптом | Причина | Что делать |
|---|---|---|
| JSON обрезан на 64 КБ | CLI пишет в pipe и выходит, не дожидаясь слива | направлять stdout в файловый дескриптор (в `tools/figma/cli.mjs` это уже сделано) |
| `getStyleById` падает | `documentAccess: dynamic-page` | читать стили заранее через `getLocalTextStylesAsync` |
| У заливки нет `imageRef` | новое API отдаёт `imageHash` | брать `getImageByHash(fill.imageHash)` |
| Иконка выгрузилась 48×48 при узле 47×47 | экспорт округляет до целого | размер задавать по узлу, а не по SVG |

## Проверка скила

На проекте, где уже собран блок: экспорт должен дать `spec.json`, `crop.png` и
ассеты, а `measure` — 0 нарушений. Если `measure` красный после экспорта —
дефект в сборке, а не в экспорте: спека и кроп сняты с одного узла.
