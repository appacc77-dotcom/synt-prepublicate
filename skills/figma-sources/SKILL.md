# figma-sources

Отвечает на один вопрос: **из какого состояния файла сделана выгрузка и не
устарела ли она**. Не собирает вёрстку — это дело `figma-export` и `figma-build`.

## Кто главный

| Источник | Роль | Свежесть |
|---|---|---|
| Мост `figma-agent` | **истина**: всё, что попадает в вёрстку | самая новая — открытый документ, включая несохранённое |
| REST API `api.figma.com` | сверка структуры и версии | сохранённая версия облака, может отставать от моста |
| Архив `.fig` | независимая сверка картинок и текстов | снимок на дату, может быть от другого файла |

Порядок свежести обычно такой: **мост новее облака, облако новее `.fig`**.
Если мост и сверка расходятся — прав мост, расхождение идёт в `docs/decisions.md`.

## Механизм проверки

**Отпечаток содержимого.** При выгрузке в спеку пишется `fingerprint` —
контрольная сумма по строкам `id|x|y|w|h|текст` всех узлов секции. Та же
функция считается на стороне моста (`tools/figma/fingerprint.js`). Совпали —
секция не менялась после выгрузки.

**Версия облака.** Спека хранит `cloudVersion` — версию файла на сервере в момент
выгрузки. Если текущая версия API другая, облако ушло вперёд.

## Команды

```bash
npm run api meta                  # версия облака, страницы → live/api.json
npm run verify                    # все доступные сверки
npm run verify -- --limit 5       # только первые 5 секций (быстрый прогон)
npm run verify -- --fig <file.fig>  # плюс сверка с архивом
```

`npm run verify` проверяет:

| Проверка | Что ловит | Обязательная |
|---|---|---|
| экспорт соответствует мосту | секцию изменили после выгрузки | да, если мост ответил |
| экспорт снят с актуальной версии облака | облако ушло вперёд | да, если версия есть в спеках |
| наши страницы есть в API | страницу переименовали или удалили | да, если API ответил |
| секции совпадают с API | секцию переименовали | да, если API ответил |
| фреймы страниц совпадают | изменился размер страницы | да, если API ответил |
| картинки совпадают с `.fig` | выгрузка потеряла или испортила байты | да, если `.fig` передан |
| тексты есть в `.fig` | текст пропал при выгрузке | да, если `.fig` передан |

Недоступность вспомогательного источника (429, нет токена, нет `.fig`) — **не
провал**: строка помечается как пропущенная сверка, код возврата 0. Провал — это
когда источник ответил и данные разошлись.

## Границы REST API

- `/styles` и `/components` отдают **только опубликованные** в библиотеку. Если
  стили локальные, вернётся пусто — это не ошибка, локальные видит только мост.
- `?depth=2` отдаёт фреймы с пустыми `children`; секции берутся эндпоинтом
  `/nodes?ids=<frame>&depth=1`.
- Лимит запросов: серия обращений ловит 429. В клиенте повтор с паузой
  1→8 с и пауза 300 мс между запросами. Не частите: `--limit` для быстрых прогонов.

## Токен

`FIGMA_TOKEN` в окружении или путь в `api.tokenFile` (`design/figma/project.json`).
Токен не печатается и не попадает в артефакты. Нет токена — сверка с API просто
пропускается, конвейер работает дальше.

## Что делать при расхождении

1. `экспорт соответствует мосту` — ✗: секцию изменили, перевыгрузить
   `npm run export -- <id> --name <section>`.
2. `экспорт снят с актуальной версии облака` — ✗: облако ушло вперёд, но мост
   новее; перевыгрузка снимет новое состояние и запишет новую версию.
3. `картинки/тексты с .fig` — ✗: либо `.fig` от другого файла, либо выгрузка
   потеряла данные. Сверить `fileKey` в `meta.json` и в `project.json`.
