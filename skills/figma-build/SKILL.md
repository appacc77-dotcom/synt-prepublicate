# figma-build

Превращает `spec.json` в компонент. Результат считается сделанным не когда
«выглядит похоже», а когда `measure` зелёный и `compare` не хуже прошлого прогона.

## Когда брать

- есть `design/figma/pages/<page>/<section>/{spec.json, crop.png, assets/}`;
- нужен новый компонент или секция;
- нужно пересобрать блок после изменения макета.

## Когда не брать

- нет спеки и кропа — сначала `figma-export`;
- правка по замечанию приёмки — это дефект, а не сборка: чинится по числу;
- нужен дизайн-вариант, которого нет в макете — это решение владельца, не код.

## Вход

| Что | Откуда |
|---|---|
| `spec.json` | `figma-export`: узлы, координаты, текст, заливки, авто-раскладка |
| `crop.png` | эталон той же секции в масштабе 1 |
| `assets/img`, `assets/svg` | фото по `imageHash`, иконки по главному компоненту |
| `tokens.css`, `typography.css` | `npm run ds:tokens`, руками не править |

## Таблица перевода: Figma → CSS

Спека отдаёт свойства, а не готовый CSS. Перевод однозначный — если значения
нет в спеке, его не выдумывают.

| В спеке | В CSS |
|---|---|
| `sizing.h: FILL` | `width: 100%` или `flex: 1` в ряду |
| `sizing.h: HUG` | `width: fit-content` (в колонке — не задавать) |
| `sizing.h` нет (FIXED) | `width: <w>px` |
| `sizing.v: HUG` | высоту не задавать |
| `limits.maxW` | `max-width: <px>px` |
| `autoLayout.primary: MAX / CENTER / MIN` | `justify-content: space-between / center / flex-start` |
| `autoLayout.counter: MIN / CENTER / MAX` | `align-items: flex-start / center / flex-end` |
| `autoLayout.gap` | `gap` |
| `autoLayout.pad: [t, r, b, l]` | `padding` |
| `textCase: UPPER` | `text-transform: uppercase` |
| `textAlign: CENTER / RIGHT` | `text-align: center / right` |
| `textDecoration: UNDERLINE` | `text-decoration: underline` |
| `rotation: -90` | `transform: rotate(-90deg)` |
| `effects: DROP_SHADOW` | `box-shadow: <x> <y> <radius> <color>` |
| `effects: BACKGROUND_BLUR` | `backdrop-filter: blur(<radius>px)` |
| `fills: GRADIENT_*` + `gradientStops` | `linear-gradient(<angle>, stop1, stop2)` |
| `fills: IMAGE` + `imageTransform` | `background-size` / `background-position` по формуле |
| `bound` | какое имя токена подставить в `var(--…)` |
| `props` у инстанса | пропсы компонента (`theme`, `size`, `caps`…) |

Паддинг и `gap` берутся с того узла, где они записаны. Если в макете паддинг у
вложенного слоя, а не у секции — паддинг идёт на этот слой, а не на секцию.

## Порядок

1. **Прочитать спеку, а не кроп.** Из `spec.json` выписать дерево до глубины
   3: имена, размеры, `autoLayout`, `fills`, `styleName`. Кроп нужен на шаге
   проверки, а не на шаге сочинения.
2. **Разметить.** Каждому узлу — элемент с `data-figma-node="<id>"`. Узлы
   глубины ≤ 2 обязательны: без них ворота красные. Служебный фрейм, который
   разметка схлопывает, вешается на тот же элемент через пробел:
   `<section data-figma-node="79:105 79:106">`.
3. **Разложить.** `autoLayout.mode` → `flex`/`grid`, `gap` → `--space-*`,
   `pad` → `--space-*`. Абсолютные координаты из спеки — для проверки, а не для
   `position: absolute`.
4. **Текст.** Класс `.t-<styleName>` из `typography.css`. Никаких `font-size`
   литералом: кегль, интерлиньяж и трекинг уже там.
5. **Цвета и радиусы.** `var(--color-*)`, `var(--radius-*)`. Hex в компоненте —
   дефект, даже если совпал с макетом.
6. **Картинки.** `scaleMode: FILL` → `object-fit: cover`. `imageTransform` —
   это кроп источника, а не `object-position`: переносить осознанно, а не
   подбирать на глаз.
7. **Иконки.** Размер — по узлу, а не по SVG: файл может быть 48×48 при узле
   47×47. Внутри — `width: 100%`.
8. **Проверить.** `npm run build` → `npm run measure` → `npm run shot` →
   `npm run compare`.
9. **Отчёт с числами.** Δ max, покрытие обязательных узлов, пиксель.
10. **Опубликовать.** `npm run previews` → `npm run structure`. Секция не
    считается сданной, пока её нет на `/structure.html` с парой
    «Figma / сделано»: страница собирается из артефактов, но только если её
    пересобирать.

## Правила, без которых не сходится

- **Компонент не знает, где стоит.** Ширина из контента и паддингов. В hero
  кнопка 303 px — это `16 + 249 + 8 + 14 + 16`, а не `width: 303px`.
- **Размеры секции — из спеки.** Высота и ширина секции допустимы как числа:
  это факт макета, а не подгонка.
- **Атрибут на каждый значимый узел.** Текст, кнопка, картинка, иконка — все.
  Чем больше размечено, тем меньше ворот молчит.
- **Ничего не додумывать.** Нет состояния, текста или отступа в спеке — значит
  их нет. Вопрос — в `decisions.md`.

## Что выяснилось на второй секции

- **Высота строки в Figma округлена.** H4 38,57 → 39, script-m 71,4 → 71,
  script-xl 68,75 → 69. Высота текстового узла = округлённая строка × число
  строк. Если оставить дробь, каждый блок расходится на 0,3–1,3 px и ошибка
  копится вниз по дереву: на `pain` это дало 21 красную строку из 29.
- **Ширина текстового блока — часть макета.** Ставится `max-width` из спеки
  (539 у заголовка, 473 у лида). Без него высота совпадёт, а переносы строк
  будут другими: лид ломается после «опоры,» вместо «нет», и это видно на
  кропе, но не в замере. Ширину сверяем наравне с остальными числами.
- **Фон с `imageTransform`.** Размер: `100%/m00` и `100%/m11`, позиция:
  `m02/(1−m00)` и `m12/(1−m11)`. Для `pain`: 190,07 % × 167,32 %, позиция
  `0% 42,68 %`.
- **`filters` запекаются в изображение, а не переносятся в CSS.** Причём не по
  формуле: `2^exposure` выжигает светá в 255 (у pain плоский участок выходил
  255 против 243 в макете), значит Figma применяет кривую с поджатием светов, а
  не умножение. Кривая снимается с **рендера Figma**:

  ```bash
  npm run shot -- .<class> .screens/<slug>-raw.png 1440
  npm run tone:fit -- design/figma/pages/<page>/<section>/crop.png .screens/<slug>-raw.png
  npm run bake -- <исходник> public/img/<slug>.jpg --affine <коэффициенты>
  ```

  Это не подбор на глаз: коэффициенты выводятся из того, что нарисовала Figma,
  и записываются в `pages/<page>/<section>/image.json` вместе с провенансом. У pain
  результат — средняя 4,14 против 11,49 при умножении.

## Когда `measure` красный

Смотреть не на число, а на то, какое из четырёх поехало:

| Что | Куда смотреть |
|---|---|
| `x`, `y` | раскладка: не тот `gap`, `align`, лишний обёрточный блок |
| `w` | ширина из контента: шрифт, трекинг, паддинг, `min-width` |
| `h` | интерлиньяж, число строк, вертикальный паддинг |
| узел не найден | забыт `data-figma-node` или неверный id |
| «вне спеки» | атрибут скопирован из другой секции |

Три итерации по одному и тому же числу — стоп. Значит, расходится спека или
шрифт, и это уже не задача вёрстки.

## Стоп-условия

- нужного значения нет в токенах — не выдумывать px, а вынести в `decisions.md`;
- спека расходится с кропом (размер, отступ, кегль) — чинится спека;
- три красных итерации по одному числу;
- для прохождения ворот требуется нарушить правило (вписать ширину, покрасить
  hex-ом) — это `blocked`, а не компромисс.

## Проверено на практике

Секция `hero` (1440×780, 14 узлов): собрана с первого прохода по этой процедуре —
`measure` 0 нарушений, Δ max 0,11 px, 8 узлов размечено, обязательные 100 %;
пиксель 1,81 при 1,04 % пикселей > 16. Для сравнения, ручная сборка того же
блока до появления ворот давала 3,52 и 2,25 %.

## Антипаттерны

| Что делали | Чем кончилось |
|---|---|
| `width: 303px` у варианта кнопки | восемь таких правок, каждая привязана к месту вызова |
| `font-size: 64px` литералом | 358 литералов в прошлой версии, токены перестали работать |
| подгонка высоты секции | секция сошлась, внутри оказался не тот компонент |
| `position: absolute` по координатам из спеки | ломается на первом же изменении контента |
| сверка «на глаз» по кропу | дефект находят на приёмке, а не при сборке |
