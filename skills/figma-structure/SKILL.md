# figma-structure

Показывает, что уже перенесено, что ждёт и насколько точно. Единственный шаг,
который смотрит не в Figma, а на **результат сборки** — поэтому он и отдельный.

## Когда брать

- **в начале**: выгрузить все секции файла и увидеть карту целиком;
- **после каждого блока**: снять превью и опубликовать сравнение;
- перед отчётом владельцу: числа берутся со страницы, а не пересказываются.

## Когда не брать

- файл не открыт или мост не подключён — сначала `figma-intake`;
- нужны числа по одной секции — это `figma-gates`.

## Порядок

```bash
npm run intake       # снимок файла: страницы, фреймы, секции
npm run structure    # собрать данные страницы и разложить превью
npm run export:all   # выгрузить все секции, у которых ещё нет спеки
npm run structure    # пересобрать: теперь у всех есть эталон
npm run build
npm run previews     # снять собранные секции Playwright'ом
npm run structure    # пересобрать: появятся пары «Figma / сделано»
```

`export:all` идемпотентен: повторный запуск догружает только недостающее.

## Что откуда берётся

| Что на странице | Источник |
|---|---|
| страницы и секции, их размеры и `y` | `design/figma/live/structure.json` (дети канонического фрейма) |
| статус | наличие `spec.json` → `gate.json` → `pixel.json` в `pages/<page>/<section>/` |
| числа геометрии | `pages/<page>/<section>/gate.json` |
| числа пикселя | `pages/<page>/<section>/pixel.json` |
| превью «Figma» | `pages/<page>/<section>/crop.png` → `public/structure/<slug>-figma.png` |
| превью «сделано» | `.screens/<slug>.png` → `public/structure/<slug>-site.png` |

Статусы: `не выгружен` → `выгружен` → `геометрия ок` → `зелёный`; `красные ворота`,
если `gate.ok === false`. Ничего не пишется руками — страница не может разойтись
с кодом.

## Что на карточке блока

Две колонки: слева — имя, статус, узел, счётчики выгруженного (узлов, фото с
разбивкой jpg/png, svg, вес), числа геометрии и пикселя; справа — пара превью
«Figma / сделано», кликабельная в полный размер.

Кнопка **«копировать»** кладёт в буфер готовую постановку задачи: узел, размеры,
пути к `spec.json` и `crop.png`, счётчики, числа и статус. Дальше остаётся
дописать, что именно доработать — id и пути переписывать не нужно.

Сверху: фильтр по статусу, поиск по имени и id (`Cmd+K`), счётчик «N из 46»,
переходы по страницам со счётчиком «выгружено/всего».

## Правило изменения страницы

Устройство страницы (что на карточке, какие разрезы, как обновляется превью) —
решение владельца. Перед любой правкой спросить, как именно её модифицируем, и не
менять молча. Данные добавлять можно свободно: они выводятся из артефактов.

## Свои настройки

Порты и пути не берутся из других проектов:

| Переменная | Значение | Для чего |
|---|---|---|
| `PREVIEWS_PORT` | 4334 | локальный сервер при съёмке превью |
| `SHOT_PORT` | 4330 | одиночный снимок |
| — | 4332 | замер геометрии |

Превью лежат в `public/structure/`, снимки — в `.screens/` (не коммитится).

## Стоп-условия

- `structure.json` собран по другому `fileKey` — пересобрать `npm run intake`;
- секция есть в файле, но её нет на странице — это `не выгружен`, а не ошибка;
- снимок секции пустой или 0×0 — элемент скрыт, проверить разметку;
- превью «сделано» не появилось после сборки — `data-figma-node` не совпадает
  с id из спеки.
