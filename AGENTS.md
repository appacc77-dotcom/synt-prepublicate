# AGENTS.md — Syntonia

Читается агентом до любых изменений. Здесь: что является истиной, что можно
трогать и когда работа считается сделанной. Если правило мешает — остановись и
спроси, а не обходи.

## 0. Проект и его состояние

Syntonia — сайт по макету Figma: Astro + обычный CSS + данные, без React,
Tailwind и CMS. Ценность проекта — не сайт, а проверяемый конвейер
Figma → спецификация → компоненты → страницы → ворота.

**06.11.2026 проект перезапущен.** Готовый сайт (48 компонентов, 13 страниц)
удалён: он был собран без ворот, и приёмка показала escape rate 33% — 5 дефектов
из 15 карточек после «готово». Удалённое восстановимо: git-тег
`pre-reset-2026-11-06`. Подробности — [`STATUS.md`](STATUS.md).

**Объём — все семь страниц файла** (home, practice, library, masters, method,
booking, quiz): он выводится из экспорта `design/figma/pages/**` (решение 353),
адреса — `design/figma/project.json` → `routes`. Новая страница или секция
появляется в объёме только через экспорт — не руками в коде. Ограничение
«только Home» от 06.11.2026 снято расширением объёма владельцем.

Актуальное состояние — [`STATUS.md`](STATUS.md) (собирается `node tools/status.mjs --write`).
Этап 1 студии — перенос макета — в доработке: все секции собраны, закрытие —
по реестрам `design/figma/invented.json` (изобретённое) и `docs/debts.json`
(долги дизайнеру и заказчику). Задачи агенту — [`docs/AGENT-REFACTOR-TASKS.md`](docs/AGENT-REFACTOR-TASKS.md).
Процесс — [`docs/system/PROCESS.md`](docs/system/PROCESS.md) (P0–P7, G0–G3).
Роли и контракты — [`docs/system/README.md`](docs/system/README.md).

## 1. Источники истины (по приоритету)

**Главный источник — мост `figma-agent` к открытому файлу.** Из него берётся всё,
что попадает в вёрстку: спеки, кропы, ассеты, токены, стили.

Два вспомогательных источника — **только для сверки и поиска**, не для сборки:

| Источник | Чем полезен | Чем не годится |
|---|---|---|
| Мост (`figma-agent`) | всё, что видит плагин: свойства узлов, переменные, варианты, экспорт | требует открытого Figma и живого соединения |
| REST API (`api.figma.com`) | версия файла, проверка страниц, фреймов и секций без приложения | только опубликованные стили и компоненты, лимит запросов (429) |
| `.fig` (архив) | независимая сверка картинок и текстов, работает офлайн | снимок на дату, может быть от другого `fileKey` |

Если мост и сверка расходятся — прав мост, а расхождение записывается в
`docs/decisions.md`. Сверка не чинит вёрстку, она показывает, что что-то
изменилось в файле или потерялось при выгрузке.

1. `docs/decisions.md` — принятые решения. Выше кода.
2. Живой файл: `figma-agent` к открытому документу (`fileKey` в
   `design/figma/project.json`).
3. `design/figma/live/*.json` — снимки файла: структура, дизайн-система, реальность,
   полный дамп `document.json`.
4. `design/figma/pages/<page>/<section>/spec.json` — числа секции для замера (P2).
5. `design/figma/pages/<page>/<section>/crop.png` — эталон, экспортированный с узла (P3).
6. Код `src/` — реализация, не истина.

Два правила важнее остальных:

- **Число без `fileKey` — не число.** Он лежит в `design/figma/project.json`.
- **Число без замера — не число.** Геометрия проверяется `npm run measure`,
  пиксель — `npm run compare`; «на глаз сошлось» не считается.

## 2. Принципы переноса

Действуют всегда, в любом режиме.

1. **Единица работы — компонент, единица приёмки — тоже.** Страница — композиция,
   а не поле для подгонки.
2. **Эталон — рендер узла, не дерево.** Кроп снимается с живого узла
   (`figma-agent export-png`) и сверяется снимком страницы.
3. **Компонент не знает, где стоит.** Ни `width`, ни `margin`, ни `font-size` под
   конкретное место вызова. Если размер не сошёлся — виноват шрифт, трекинг или
   паддинг, а не место вызова.
4. **Только токены.** Hex и «похожий» px в компоненте — дефект. Токены — из
   сгенерированного файла, не набранные руками.
5. **Имена 1:1 с Figma.** Набор `btn-primary` → `btn-primary.astro`. Новые
   компоненты библиотеки — в `src/components/ds/`.
6. **`data-figma-node`** на каждой секции: без него нечего сравнивать.
7. **Не додумываем.** Нет состояния, текста, цены или отступа в макете — значит
   их нет. Вопрос — в `decisions.md`, а не в код.
8. **Слой и этап — разные вещи.** Воспроизведение макета (`base`) и наши
   дополнения (`enhancements`) проверяются отдельно: `--profile accept-stage1`
   и `--profile accept-stage2`. Дополнение обязано быть отключаемым
   (`data-enhancements=off`) и не имеет права менять основу без записи в
   `allowedSections`. Проверки описаны в `tools/checks.json`, а не списком в коде.
9. **Мобилки нет.** Макетов 390/768 в файле нет, и адаптив не изобретается:
   сжать вёрстку «по месту» — это не перенос, а догадка. Нет макета — нет
   адаптива, и это фиксируется как отсутствие, а не чинится на глаз. Появится
   макет — появится слой.
10. **Контент-заглушки помечаются.** Цены и длительности из файла не подтверждены
   заказчиком: они допустимы в вёрстке и блокируют публикацию, а не карточку.

## 3. Границы

- **Runtime:** `src/`, `public/`, `astro.config.mjs`, `tsconfig.json`,
  `package.json`. Публикуется `dist/`.
- **Не трогать без карточки:** `docs/system/**` (процесс), `package.json`
  (зависимости), `design/figma/live/**` (снимки файла).
- **Только чтение, генерируемое:** `src/styles/tokens.css`,
  `src/styles/typography.css` (пишет `npm run ds:tokens`), `design/figma/pages/**`.
- **Общий слой** — `src/styles/base.css`, шапка, подвал — меняется отдельной
  карточкой, а не «попутно».
- **Новые зависимости** — только с согласованием.
- **Мастерская и выпуск — разные вещи.** Мастерская: весь репозиторий (спеки,
  кропы, отчёты, студийные страницы, `design/`). Выпуск: только файлы сайта,
  перечисленные в `site-files.json`, — он уезжает на хостинг и обязан
  собираться без `design/` и `docs/`. Публикует только зелёный прогон:
  `npm run site:export` → `npm run site:release` (решения 397–399).
- **`tools/lib/`** — только чистые функции формата (декодер PNG, чтение ZIP):
  без состояния, без знания о проекте, импорты — `node:` и соседние файлы.
  Проверяется воротами `lib-purity`. Дублировать формат по инструментам
  нельзя: три копии декодера уже разошлись один раз (решение 393).
- **Git:** один коммит — одна мысль. **Коммит и пуш — один шаг:** хук
  `tools/git-hooks/post-commit` отправляет ветку, если GitHub доступен, и
  молча пропускает, если нет (коммит при этом остаётся локальным и об этом
  сказано). Включить в новом клоне: `npm run hooks`. `reset --hard`, `rebase`,
  `push --force` — не без просьбы.

## 4. Задача = карточка

Одна карточка — один запуск. В карточке: `id`, единица (`component` / `section`),
узел Figma, `figma_version`, срез `spec`, кроп, `files:`, команда приёмки,
`content_status`.

- работа начинается только при заполненном Definition of Ready
  ([шаблон](docs/system/templates/card.md));
- меняются только файлы из `files:`; нужен ещё файл — `blocked`, а не расширение
  правки;
- по завершении — отчёт с числами ([шаблон](docs/system/templates/report.md)),
  статус `review`, не `done`;
- карточку в `done` переводит приёмка, не автор.

Доска — внешний DSH Kanban (`DSH_BOARD_URL` или прокси `/kanban`). Перед работой:
`kanban_board { next: true }`; закончил — `kanban_card { action: "move", cardId,
column: "review" }`. `board.json` руками не править: плагин проверяет DoR и
ведёт историю. Как это устроено — [`docs/system/KANBAN.md`](docs/system/KANBAN.md).

## 5. Фазовая дисциплина

Фазы P0–P7 последовательны. **Отсутствие инструмента — причина его сделать, а не
обойти.** Прошлый прогон обошёл именно так: «ворот пока нет, соберём секции» —
и получил 13 страниц без единой проверки.

Пока фаза не закрыта, запрещено начинать следующую:

| Фаза | Закрывается | Сейчас |
|---|---|---|
| P0 Ingest | `design/figma/live/*.json` + `fileKey` | **готово** |
| P1 Reality | числа по файлу (масштабы, ширины) | **готово** |
| G0 | 0 открытых 🔴 в `decisions.md` | **закрыт** |
| P2 Resolve | `design/figma/pages/<page>/<section>/spec.json` | идёт |
| P3 Model | токены, кропы | **готово** |
| P4 Components | G1: `measure` зелёный по каждому компоненту | собраны все секции объёма; приёмка — `conveyor check --all` |

**Не перескакивать:** следующая фаза начинается, только когда у предыдущей есть
артефакт на диске. «Соберём одну главную, чтобы посмотреть» — не аргумент.

## 6. Проверки

```bash
npm run intake                                 # снимок живого файла; exit 1 при чужом файле
npm run document                               # полный дамп: переменные, стили, все узлы со свойствами
npm run export -- <nodeId> --name <slug>       # кроп + ассеты + spec.json секции
npm run ds:tokens                              # токены и типографика из живого файла
npm run build                                  # dist/
npm run shot -- .hero .screens/hero.png 1440   # снимок элемента
npm run measure -- design/figma/pages/home/hero/spec.json   # геометрия по data-figma-node
npm run compare -- <crop.png> <shot.png>       # пиксель, без внешних зависимостей
npm run previews                               # снять собранные секции Playwright'ом
npm run structure                              # пересобрать /structure.html из артефактов
npm run stamp                                  # отпечатки содержимого и версия облака в спеки
npm run verify                                 # сверка: экспорт ↔ мост (облачное API — только с --api)
npm run bindings                               # цвета в спеках ↔ значения переменных
npm run tokens:check                           # var(--x) без определения — молча обнуляет свойство
npm run interactive                            # нажатия меняют состояние, а не только атрибут
npm run motion                                 # у каждого интерактивного элемента есть переход
npm run motion:check                           # движение описано в манифесте, длительности из токенов
npm run motion:manifest                        # пересобрать манифест движения
npm run layout                                 # на ширине макета нет горизонтальной прокрутки
npm run invented                               # нет вёрстки под ширины, которых нет в макете
npm run states                                 # контент всех состояний секции собран
npm run images                                 # фоновые картинки не растянуты
npm run gen -- plan <page>/<section>            # черновик разметки: что соберётся, что руками
npm run gen -- emit --all                       # src/components/_gen/*.astro
npm run gen:report                              # покрытие черновика и список overrides
```

**Облачное API — опция.** По умолчанию сверка идёт только с мостом: REST
отдаёт 429 и видит лишь опубликованные стили. Включить: `npm run verify -- --api`
или `FIGMA_API=1`.

**Проверка актуальности.** В каждой спеке есть `fingerprint` — контрольная сумма
содержимого секции, и `cloudVersion` — версия файла на сервере в момент снятия.
`npm run verify` заново читает секции мостом и сравнивает отпечатки: если
разошлись, экспорт устарел. Недоступность API или отсутствие `.fig` — пропущенная
сверка, а не провал.

`measure` — ворота геометрии: элемент с `data-figma-node` сверяется с узлом из `spec.json`
по абсолютным координатам от корня секции. Красные, если расхождение больше 1 px,
если у узла глубины ≤ 2 нет своего элемента или если атрибут ссылается на узел вне спеки.
`compare` — сигнал регрессии, не критерий приёмки: текст растеризуется по-разному,
фон и заливки совпадают. Ориентир: hero — средняя 1,76, пикселей > 16 — 0,98 %.

**Любое утверждение о соответствии подкрепляется числом и командой**, которая это
число получила. Скриншот без числа — впечатление, а не проверка.

**Публикация обязательна — в мастерской.** Секция не считается сданной, пока
её нет на `/structure.html` с парой «Figma / сделано» и числами: `npm run
previews` → `npm run structure`. Страница собирается из артефактов, поэтому
расходиться с кодом не может — но только если её пересобирать.

На сайт заказчика эта страница не уезжает: `structure.html`, `ds.html` и
студийные превью — мастерская (решение 400). Выпуск собирается по
`site-files.json` и проверяется воротами `site-clean` и `site-contract`.

## 7. Стоп-условия

Остановиться и вернуть `blocked` с причиной, если:

- нет кропа или спеки по единице, либо `fileKey` живого файла не совпал с
  `project.json` (работать по чужому файлу нельзя);
- в `decisions.md` открыт 🔴 по этой единице;
- spec расходится с кропом (тогда чинится spec, а не вёрстка);
- нужен файл вне `files:`;
- три итерации подряд красные по одному и тому же числу;
- чтобы пройти проверку, нужно нарушить §2 — например, вписать ширину;
- задача требует фазы, которая не закрыта.

В отчёте: что отсутствует или противоречит, варианты решения, что уже проверено.
Решает владелец.

## 8. Документы: две версии

Правило проекта: у документа две версии — человеческая (что это значит, без имён
свойств) и агентская (id, свойства, было → стало).

- [`TUTORIAL.md`](docs/TUTORIAL.md) — учебник: от пустой папки до собранного блока;
- [`ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство и почему так;
- [`FIGMA-ISSUES.md`](docs/FIGMA-ISSUES.md) — что поправить в макете, с числами;
- [`decisions.md`](docs/decisions.md) — принятые решения, append-only;
- [`RUNBOOK.md`](docs/RUNBOOK.md) — холодный старт на новом сайте;
- [`DEFECTS.md`](docs/DEFECTS.md) — каждый найденный дефект и ворота, которые его ловят;
- `reports/**` — числа и вердикты.

## 9. Definition of Done

**Компонент:**

- [ ] имя = имя набора Figma, API = пропсы Figma;
- [ ] нет размеров, зависящих от места вызова;
- [ ] только токены;
- [ ] `data-figma-node`;
- [ ] есть в `/ds` во всех вариантах;
- [ ] кроп-дифф в пороге;
- [ ] **движение:** у каждого интерактивного состояния есть переход
      (`hover`, `focus-visible`, `active`, открытие, смена) — длительность из
      `src/styles/motion.css`, а не числом в компоненте. Базовый слой
      `motion.css` покрывает цвет и прозрачность у ссылок, кнопок и `summary`;
      геометрию он не трогает никогда;
- [ ] **движение описано в манифесте:** `design/motion/motion.json` — запись на
      каждое объявление с `status` и номером решения. `npm run motion:check`
      падает, если анимация появилась без записи или длительность задана
      числом. Манифест пересобирается `npm run motion:manifest`.

**Секция:**

- [ ] собрана из компонентов и данных, без самодельных примитивов;
- [ ] высоты и якоря совпадают с эталоном, числа в отчёте;
- [ ] на ширине макета нет горизонтальной прокрутки — `npm run layout`.
      Мобильной вёрстки нет: макетов 390/768 дизайнер не делал, поэтому эти
      ширины не проверяются и не сжимаются;
- [ ] сборка зелёная, консоль пустая;
- [ ] **блок живой:** `npm run interactive` показывает, что нажатия меняют
      состояние. Секция с кнопками, которые ничего не делают, — картинка;
- [ ] **переключатель показывает своё состояние:** бургер стал крестиком,
      шеврон повернулся, стрелка сменилась. Открытие, которое видно только по
      панели, читается как «ничего не произошло»;
- [ ] отчёт с человеческой частью и числами.

## 9.05 Высота, которая зависит от данных

Если блок содержит данные из файла — список, название, строку формата — его
высота задаётся `min-height`, а не `height`. В макете нарисован один вариант:
три пункта, короткое название, одна строка. В собранной секции их может быть
больше, и фиксированная высота превращает это в наложение на соседний блок
или на подвал.

Проверяется воротами `overflow`: обрезанное содержимое и заход за следующую
секцию. Осознанная обрезка помечается в разметке `data-overflow-ok` — с
комментарием, почему это замысел.

## 9.06 Что обязан нести экспорт

Спека — это не только координаты. Если в ней нет чего-то, из чего сделан
макет, вёрстка соберётся «похоже» и развалится незаметно.

| обязано быть | что будет, если нет |
|---|---|
| `fontFamily`, `fontSize`, `lineHeight`, `textTracking`, `textAlignHorizontal` | текст рисуется подставным шрифтом, строки переносятся иначе, заголовок наезжает на соседний блок |
| `x`, `y` **относительно родителя** | сложенные как абсолютные, они уводят всё содержимое за рамку |
| `imageHash` у картинки | заливка остаётся пустой, а файл в `images/` никто не найдёт |

Три вещи проверяются автоматически, потому что глазами их не видно:

- **`spec-contract`** — у спеки есть `schemaVersion`, обязательные поля на
  месте, у текста есть шрифт (или честная пометка `fontMixed`, что в файле
  смешаны стили);

- **`spec-bounds`** — узлы у рамки секции лежат внутри неё. Ловит ошибку в
  понимании координат: дерево при ней не ломается, всё просто уезжает
  целиком, и замер этого не замечает — он сверяет вёрстку с той же спекой;
- **`overflow`** — содержимое не обрезано и не залезает на соседнюю секцию.

Чего проверка **не** делает: не требует, чтобы текст влезал в свою коробку.
В Figma коробка текста часто на 10–15 px ниже строки, и это норма: текст не
режется, а выходит за границу. Смотреть надо на обрезку и наложение.

## 9.07 Черновик разметки

`tools/gen.mjs` собирает скелет секции из спеки: абсолютные координаты, текст,
заливки, кроп картинок. Это **черновик**, а не вёрстка (решение 388). Замер
у него зелёный всегда, пиксель — хуже ручного там, где текст поверх
изображений и где есть состояния.

Когда брать: новая секция с нуля, нужен точный скелет и список того, что
требует рук. Когда не брать: правка готового компонента, поведение, состояния.

Правила, которые нельзя обходить:

1. `src/components/_gen/` — не источник истины и не участник приёмки. Рабочий
   компонент живёт в `src/components/` и проходит обычный Definition of Done:
   токены, `data-figma-node`, замер, пиксель, состояния, `review`.
2. `design/gen/overrides/` — рабочий список, а не отписка: каждая запись
   означает «этот узел делается руками», с причиной и номером решения.
3. Сгенерированный файл руками не правится: `gen-drift` покраснеет. Правка —
   в генераторе или в overrides.
4. Витрины в сборке нет: калибровочная страница удалена вместе с шестью
   секциями. Нужно посмотреть черновик — соберите его и откройте разметку
   или поднимите страницу на время; в репозиторий она не возвращается.

## 9.08 Реестр ошибок (обязателен)

`docs/issues.json` — единственный источник, `docs/ISSUES.md` собирается из него
(`npm run issues:write`). **Каждая сессия заканчивается записью найденного**:
симптом, причина, решение и защита на будущее.

Запись обязана содержать `prevention`: правило (что делать иначе) и, если
возможно, ворота из `tools/checks.json`. Находка без защиты — это запись,
которая вернётся; ворота `issues` такое не пропускают.

Из этого реестра собирается цикл рефакторинга: открытые записи и записи с
`prevention.status = частично`/`планируется` — очередь работ, а не пожелания.

## 9.1 Отчёт итерации

Итерация заканчивается коммитом и пушем: хук `tools/git-hooks/post-commit`
отправляет ветку сам, если GitHub доступен, и печатает, как отправить позже,
если нет. Коммит при этом не блокируется.

Ответ заканчивается разделом **«Что посмотреть»**:

1. короткая таблица чисел, полученных командами, — замер, пиксель, элементы
   управления, вердикт прогона;
2. ссылки: структура `http://127.0.0.1:4322/structure.html`, сайт
   `http://127.0.0.1:4322/`, репозиторий
   `https://github.com/appacc77-dotcom/conveyor`;
3. строка `Коммит <hash>, запушен. Решения NNN–NNN.`;
4. если что-то не сделано или упирается в решение владельца — блок
   **«Что от вас нужно»**.

Числа не пересказываются по памяти: каждое берётся из последнего прогона
(`reports/runs/<id>/verdict.json`, `gate.json`, `pixel.json`).

## 10. Известные пробелы

Не «норма», а список того, чего нет и что нельзя обойти. Числа — из артефактов,
а не по памяти: `design/figma/pages/**/gate.json`.

- **эффекты:** шапка — `BACKGROUND_BLUR` через `backdrop-filter`, проверен.
  Остальные blur и `DROP_SHADOW` файла по страницам не сверены — проверить;
- **разметка:** по всем секциям размечено 820 узлов из 2174 (38 %, на 08.11.2026).
  Обязательные (глубина ≤ 2) покрыты на 100 %, у остальных геометрия не
  сверяется — только пиксель. `gate.json` пишет оба числа: `coverage` и `markedRatio`;
- **`/ds` собран не полностью:** страница есть и показывает 6 наборов из 54
  (11 %). Остальные 48 — не собраны; список на странице берётся из
  `design/figma/live/ds.json`, поэтому отставание видно;
- **мобильной вёрстки нет:** в файле только кадр 1440, макетов 390 и 768
  дизайнер не делал. На узком экране страница не сжимается — она шире экрана.
  Это отсутствие исходника, а не дефект вёрстки;
- **цвет фото:** кроп air-photo из Figma ярче любого корректного пересчёта того
  же JPEG (Display P3). Пока не исправлено, пиксель этой секции нельзя
  сравнивать с другими — см. [`FIGMA-ISSUES.md`](docs/FIGMA-ISSUES.md);
- на доске 28 старых карточек, ссылающихся на удалённые файлы — их нужно
  архивировать, а не выполнять;
- уставы ролей перенесены в `docs/system/agents/`; копия в `../agent-system/`
  осталась исторической и может расходиться — читать проектную.
